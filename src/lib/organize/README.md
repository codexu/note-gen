# P7 自動整理

在 V3 的「設定 → 一般 → 自動整理」啟用。預設關閉，讓使用者自行決定是否讓背景掃描讀取 vault 內容。停用後中止新掃描，已送出的提案和復原紀錄仍可從「等你定」處理。掃描和提案都在本機執行，無需設定代理人或模型。

## 觸發與範圍

- 主視窗沒有鍵盤、指標、捲動、輸入、焦點或編輯器輸入事件滿 60 分鐘後掃描一次，每分鐘檢查。需要新的使用活動及下一段閒置時間才會再跑。切換工作區、啟用開關或切回 V3 時重新計時。讀檔期間若恢復使用、切換工作區或索引版本變動，就捨棄結果。
- 索引須就緒。依既有大 vault 效能規格，超過 10,000 篇 Markdown 時略過。單次循環最多讀 64 篇舊筆記，每篇最多 64 KiB，四路並行。依路徑排序取一批，下次從該批之後繼續。單次最多提出五項，同一 vault 待決提案也最多五項。
- 排除每日筆記資料夾、無法確認修改時間或最近一小時內變動的筆記。同一筆記每輪只參與一項提案，既有待決提案使用的筆記也先略過。近期任務保留提案的類型、路徑、建議值和修改時間，避免重複問同一版本。

## 偵測

- **合併**只在同資料夾、相同 frontmatter `type`、相同 frontmatter 原文及至少 40 字元的本文之間比較。本文完全相同時保留原樣。近似筆記的檔名和內文以正規化字元三元組的 Jaccard 分數比對，門檻分別為 0.60 和 0.90。近似合併排除任務、索引連結及區塊 ID，並以分隔線保留兩份本文。來源若有別名或任一索引連結可能指向它，即略過移除。合併比較限單批讀入的筆記。
- **標籤**以相同類型且包含目前所有標籤的同儕筆記為樣本。至少三篇且占樣本 75% 同時使用該標籤才提出。每次補一個 YAML 標籤，保留其他欄位；無法安全編輯的 YAML 略過。
- **關聯**重用未連結提及的比對與雙鏈改寫。以索引中的檔名或別名為準，至少四個 ASCII 字元或三個非純 ASCII 字元的名稱，且目標必須唯一。每篇依前 16 Ki 字元篩出最多 128 個命中的名稱，每次只改寫一處未連結的提及，排除已連到同一目標的筆記以及註解、程式碼或既有連結中的提及。

## 審核、復原與資料

「等你定」從 `agent_tasks` 投影 `organize` 類型的草稿，合併在同一項顯示保留與移除的筆記。收下時重新檢查工作區、檔案修改時間、快照與合併來源的索引連結。拒絕只更新草稿。

修改前先在本機 `note.db` 的 `organize_undo` 寫入每個受影響檔案的前後快照。合併若有兩個步驟，先寫保留筆記，再刪除來源。完成後可從通知或「等你定 → 整理紀錄」一鍵復原。復原比對套用後內容，對已刪檔案採用獨占建立，避免蓋掉後續編輯或同名重建檔案。中途失敗時嘗試回滾。程序中斷或回滾未完成時，整理紀錄會保留「還原原始筆記」，可從符合快照的部分狀態復原。紀錄以工作區隔離，重啟後仍可用。SQLite 表首次使用時建立。

合併的刪除沿用本機筆記工具，整理流程不直接發出遠端刪除。備份 `note.db` 可保留還原快照。
