# P6 開工卡

在 V3 的已儲存對話串中點「新增開工卡」。總助依輸入的需求與已啟用的 P5 代理人名單提出步驟、指派、前置步驟與驗收標準。規劃呼叫沿用編輯器 AI 設定，僅產生結構化提案。也可手動建立步驟。儲存後，卡片會出現在該對話串的訊息流中，使用者按「開工」才派出任務。

## 持久化與執行

- `store.json` 的 `almanacJobCardsV1` 存開工卡、對話穩定 ID（`threadKey`）、步驟相依、驗收狀態與結果快照。主視窗以單一序列處理使用者操作和任務狀態通知。
- 每次執行先存一個 `job-step-<uuid>` 保留名額，再透過 P5 的 `enqueueAgentTask` 建立同 ID 的 `agent:<id>` 任務。SQLite 沿用 `agent_tasks`，原本的資料表格式不需遷移。P5 的 runner、工具權限、草稿及草稿審核維持原流程。這些任務的重跑與取消由開工卡管理。
- 所有開工卡合計最多 3 個已派出的步驟（含任務中心中排隊的步驟）。任務中心的並行設定可能進一步限制實際執行數。前置步驟成功執行後，下游可使用其文字回報；驗收結果或套用草稿由使用者逐條決定。取消尚未完成的步驟也會取消因此無法執行的後續步驟。
- 重開後用 P5 任務狀態核對保留名額。缺少任務列或執行中斷都顯示可重跑的失敗，重跑使用新任務 ID。先前的草稿留在既有草稿審核流程。已成功執行的步驟以快照回報到原對話，待驗收的結果投影到「等你定」。

切換 classic 會暫停開工卡派出新步驟，已送到任務中心的工作由 P5 完成。開工卡與執行紀錄在本機。回退到 P5 時可保留 `almanacJobCardsV1`，該版本會忽略此鍵，仍可使用相容的 `agent_tasks` 草稿資料。

## 複審修正（PM，2026-11-18）

- 相依滿足：前置步驟在「待驗收」或「已收下」時放行下游；**被拒絕的結果不會放行**。
- 拒絕某步：已用過它結果、但尚未被收下的下游步驟重置回「等待」，等該步重跑產生新結果後再跑。已收下的下游保留。
- 被拒絕的步驟可以重跑或取消。
- 步驟重跑、被拒絕、被取消、或因上游被拒而重置時，舊任務留在「等你定」的草稿一併丟棄，避免重複寫入。
- 已知限制：被重置的下游若當下仍在執行，P5 任務會跑完；它之後產生的草稿不會自動丟棄。
